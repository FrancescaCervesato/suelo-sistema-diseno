Accesibilidad y Auditoría de Sistema

Este portal reúne las directrices para el diseño inclusivo bajo la identidad visual de SUELO y documenta el estado de salud, completitud y consistencia del sistema actual.

1. Directrices de Accesibilidad (A11y)

Aseguramos que cada componente de SUELO sea operable, comprensible y robusto para todas las personas, respetando las pautas WCAG 2.1 AA.

2. Auditoría y Salud del Sistema

Estado actual de completitud y consistencia técnica del diseño de SUELO, construido a partir del análisis profundo del archivo Figma auditado.

Nomenclatura (Naming)

• Ciertas estructuras de componentes poseen nombres genéricos obsoletos, tales como Frame 2978 y Frame 2981.

• Se observa una mezcla entre lenguajes (Español e Inglés) dentro de las definiciones.

• Inconsistencias en nombres de propiedades tales como Estado vs State y Tipo vs Type.

Documentación del Sistema

• 0 de 41 componentes cuentan con descripciones de Figma completas.

• No se han documentado pautas de uso para los componentes interactivos principales.

• Las variables semánticas y los tokens carecen de explicaciones de contexto de uso.

Consistencia de Estructura

• El componente Card KPI, a pesar de estar marcado como OBSOLETO REEMPLAZAR, sigue publicado en la librería global.

• 2 grupos de componentes registran errores críticos en definición de propiedades, obstruyendo la inspección de Figma.

• Presencia de páginas en borrador o experimentales publicadas (ej: practica, boton transparencia).

Brechas de Completitud

• Sin variables detectadas para Modo Oscuro (Dark Mode), pese a contar con la colección llamada 'modoColor'.

• Cobertura de estados incompleta en componentes críticos (ej: no hay estados hover en inputs).

• Ausencia total de tokens para movimiento/animaciones, bordes (border-radius) y opacidades.

📋 Recomendaciones de Priorización (Plan de Acción)

Hojas de ruta sugeridas para subsanar los hallazgos en orden de urgencia de implementación.

Prioridad P1

Acciones Críticas e Inmediatas

✓ Completar descripciones y pautas en Figma para los 41 componentes base.

✓ Reparar las propiedades rotas detectadas en los 2 sets de componentes dañados.

Prioridad P2

Estandarización y Limpieza

✓ Normalizar nombres de componentes y propiedades a un idioma único (preferiblemente Español).

✓ Retirar formalmente de publicación los elementos marcados como obsoletos (Card KPI).

Prioridad P3

Mejoras de Robustez y Extensión

✓ Proveer soporte de contraste y tokens para Modo Oscuro en la colección "modoColor".

✓ Crear e incorporar tokens específicos para radio de borde (border-radius), opacidad y movimientos.

✓ Integrar requerimientos de accesibilidad como propiedades nativas de documentación.
